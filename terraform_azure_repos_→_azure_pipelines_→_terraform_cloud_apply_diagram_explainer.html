Terraform to Azure Repos → Azure Pipelines (Validate/Plan) → Terraform Cloud (Apply)

High-level architecture and flow with branch-to-workspace mapping, pipeline gates, and Terraform Cloud integration.

Key Technical Details

  • Branch → Workspace mapping: Use terraform { cloud { organization = "acme"; workspaces { tags = ["app1"] } } } + TFC workspace tags, or configure distinct workspaces dev, qa, prod and map via pipeline variables.
  • Remote state: Prefer Terraform Cloud remote backend (no local state). Keep sensitive values in TFC variables (sensitive) and Azure Key Vault for provider creds.
  • Auth: In Azure Pipelines, inject TFC_TOKEN (as secret). In Terraform, use TF_CLOUD_ORGANIZATION and workspace name or tags, or the terraform { cloud { ... } } block.
  • Plan visibility: Publish plan.out as a build artifact and post a summarized plan to the PR using a script or an extension.
  • Gates: Protect branches with required reviewers and a successful Build policy. In TFC, enable Sentinel/OPA policies before apply.
  • Security: Pull provider creds from Azure Key Vault (pipeline variable groups) and scope them per environment.
  • Apply: Use Terraform Cloud to run applies; choose Auto-apply for non-prod and manual for prod.

Minimal azure-pipelines.yml

trigger:
  branches:
    include: [ feature/*, develop, main ]

pr:
  branches:
    include: [ develop, main ]

variables:
  TF_CLOUD_ORGANIZATION: acme
  TF_WORKSPACE: $(Build.SourceBranchName)   # e.g., dev/qa/prod via branch naming

pool:
  vmImage: ubuntu-latest

steps:
- checkout: self
- task: Bash@3
  displayName: Install Terraform
  inputs:
    targetType: inline
    script: |
      curl -fsSL https://releases.hashicorp.com/terraform/1.9.5/terraform_1.9.5_linux_amd64.zip -o tf.zip
      sudo unzip -o tf.zip -d /usr/local/bin

- task: Bash@3
  displayName: Terraform fmt & validate
  inputs:
    targetType: inline
    script: |
      terraform -version
      terraform fmt -check -recursive
      terraform init
      terraform validate

- task: Bash@3
  displayName: Terraform plan (remote in Terraform Cloud)
  env:
    TF_TOKEN_app_terraform_io: $(TFC_TOKEN)  # service connection secret
  inputs:
    targetType: inline
    script: |
      export TF_CLOUD_ORGANIZATION=$(TF_CLOUD_ORGANIZATION)
      terraform init
      terraform workspace select $(TF_WORKSPACE) || terraform workspace new $(TF_WORKSPACE)
      terraform plan -out=plan.out -input=false
      terraform show -no-color plan.out > plan.txt

- publish: plan.out
  artifact: tfplan

# Optionally comment plan summary to PR using REST API or an extension.

terraform { cloud {} } example

terraform {
  cloud {
    organization = "acme"
    workspaces {
      name = var.workspace_name # or use tags = ["app1", var.env]
    }
  }
  required_version = ">= 1.5.0"
  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "~> 3.100"
    }
  }
}

Best Practices

  • Enable branch protection and mandatory CI for develop and main.
  • Run tflint and tfsec in CI for static analysis.
  • Use separate TFC workspaces per environment; avoid sharing state.
  • Store provider creds in Azure Key Vault; never hardcode secrets.
  • Gate apply with Sentinel policies and manual approvals for production.
